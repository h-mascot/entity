## medium: Concurrent bot creation can duplicate bot users and lose manifest updates

id: fnd_sig-feat-cli-command-f1df57017b-_e11d884274
category: concurrency
confidence: medium
triage: risk
status: open
feature: Node source packages/server/src/clickclack (feat_cli-command_f1df57017b)

evidence:
- packages/server/src/clickclack/bridge.ts:290-325 (ensureAgentBot)

ensureAgentBot performs a read-check-create-write sequence against a shared manifest with no lock, atomic compare/write, or re-read before persisting. Two simultaneous sendCompatibilityMessage calls for the same new agent can both miss the manifest entry, both run bot creation, and then race writing the manifest. That can create duplicate ClickClack bots/tokens and leave only one record persisted, making the other created credential unmanaged.

recommendation:
Serialize manifest mutation per manifest path/agent or use an atomic lock file around read/create/write. Re-read the manifest after acquiring the lock and before creating the bot so only one caller creates the missing record.

test analysis:
bridge.test.ts exercises sequential sends only and injects createAgentBot without concurrent calls, so the read-create-write race is never exercised.

suggested regression test:
Add a bridge test that fires two sendCompatibilityMessage calls concurrently for the same target with a delayed createAgentBot, asserts createAgentBot is called once, and asserts both results use the same bot user id.

minimum fix scope:
Guard ensureAgentBot manifest read/create/write with per-manifest locking or in-process serialization.

## medium: Seed script exits successfully without seeding any sources

id: fnd_sig-feat-config-26bfbb7d61-3fb36_58af2129ef
category: bug
confidence: medium
triage: risk
status: open
feature: Shell/workflow config seed-agent-sources.sh (feat_config_26bfbb7d61)

evidence:
- scripts/seed-agent-sources.sh:25-30
- scripts/seed-agent-sources.sh:47-70
- scripts/seed-agent-sources.sh:73-76

The script selects an endpoint and fetches the current source list, and it defines create_source, but no code invokes create_source or otherwise mutates configuration before printing Done. Any workflow using this seed script as an automation step will get a successful exit even though no seed data was applied.

recommendation:
Either call the intended seeding logic before printing Done, or rename/replace the script with an explicit validation/no-op script so callers cannot mistake it for a successful seed operation.

test analysis:
No tests are included for this shell workflow, and there is no assertion that running the script creates or updates expected sources.

suggested regression test:
Add an integration test or shell-level smoke test with a mock HTTP server that runs scripts/seed-agent-sources.sh and asserts the expected POST request(s) are made, or asserts no-op behavior if that is the intended contract.

minimum fix scope:
Add the missing top-level seeding calls or remove the misleading unused seeding functions and update the script contract.

## low: Malformed auth cookie can turn an auth failure into a 500

id: fnd_sig-feat-cli-command-f1df57017b-_1e6d958cb0
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Node source packages/server/src/clickclack (feat_cli-command_f1df57017b)

evidence:
- packages/server/src/clickclack/proxy.ts:48-56 (cookieValue)
- packages/server/src/clickclack/proxy.ts:67-75 (hasValidEntityAuth)
- packages/server/src/clickclack/proxy.ts:105-114 (requireEntityAuth)

cookieValue calls decodeURIComponent directly on user-controlled Cookie header data. If a request includes entity-clickclack-token=% or another malformed percent escape while ENTITY_API_TOKEN is set, decodeURIComponent throws before requireEntityAuth can return the intended 401 response. This makes malformed input produce an internal server error on both proxy route families.

recommendation:
Catch URIError in cookieValue and treat the malformed cookie as absent, or use a cookie parser that handles malformed values without throwing.

test analysis:
proxy.test.ts covers valid cookie, bearer token, missing token, and token stripping paths, but does not send malformed Cookie header values.

suggested regression test:
Add a proxy route test with ENTITY_API_TOKEN set and Cookie: entity-clickclack-token=% that expects 401 rather than 500.

minimum fix scope:
Wrap decodeURIComponent in cookieValue with try/catch and return an empty value for malformed matching cookie values.
