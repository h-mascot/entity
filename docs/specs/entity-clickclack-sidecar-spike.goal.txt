## Success criteria
All must be true before stopping:
1. ClickClack is pinned or vendored by a reversible mechanism in the Entity worktree, with the commit recorded and without copying arbitrary generated artifacts.
2. Entity can start or document/start ClickClack as a local private sidecar on `127.0.0.1:3091` using an Entity-managed data directory.
3. Entity server exposes proxy routes for the ClickClack SPA/API under a non-conflicting namespace, for example `/clickclack/*` and `/api/clickclack/*`, without breaking existing Entity routes.
4. A minimal identity/bootstrap bridge exists for the spike: one human operator and at least one Entity agent/bot user can exist in ClickClack. Use the safest dev-only bridge if full auth integration is too large, and mark it clearly as dev-only.
5. Existing `/api/chat/send` compatibility is preserved or adapted enough to post a user message into ClickClack and create one bot-authored agent reply in ClickClack for a selected Entity agent.
6. Proof exists for one human send and one Entity agent reply flowing through ClickClack. Acceptable proof: API transcript, HTTP responses, DB rows, and browser screenshot of proxied chat UI if the SPA can run.
7. Validation runs at least: `npm --prefix packages/app run build`, `cd packages/server && npm run build`, and targeted server tests or a documented stronger/smaller substitute if the sidecar changes are script-only.
8. `docs/plans/ACTIVE_PLAN.md` is updated with actual progress, files touched, commands run, proof, blockers, and resume instructions.
9. The final report states whether the sidecar path is viable, blocked, or should fall back.
